# `model_constructor/blocks/experiments/`

Experimental `torch.nn.Module` components for robot-policy architectures. Every registry key in this directory is registered in [`../register.py`](../register.py) with `signature_policy="strict"` and the `"experimental"` tag.

These blocks implement flow matching, VQ-VAE, mixture-of-experts, vision and VLM backbones, mutual-information estimators, plus DSRL / ResFit reinforcement-learning-flavored actors and value functions, plus a batched-inference wrapper around the OpenPI vision-language-action model.

If you're new to the research terms (flow matching, CFG, VQ-VAE, MoE, DSRL, ResFit, OpenPI, RadioV3, DA3), see [docs/GLOSSARY.md](../../../docs/GLOSSARY.md) before reading the code.

### DSRL — [`dsrl/`](dsrl/)

Reinforcement-learning-flavored components: Q-function (value network), noise-latent actor (flow-matching-style actor in a latent action space), plus processor modules that ingest multi-camera images + depth + proprioception + action.

The actor and Q-function expect already-flattened latent feature inputs; the `*_processor` modules produce those flattened features from raw observation dicts. The `dsrl_img_encoder` is a three-camera ResNet34 encoder group.

### ResFit — [`resfit/`](resfit/)

Residual actor + Q-function pair. The actor outputs a small residual action (scaled by 0.25 in [`resfit/residual_actor.py`](resfit/residual_actor.py) ~line 222) on top of a base action; the Q-function is a multi-head ensemble critic.

Unlike the DSRL versions, the ResFit actor/Q-function each internally instantiate the ResNet34 encoder group and the processor — they take raw multi-camera observation dicts as input.

## Present in code but not registered

These classes exist on disk but have no entry in [`../register.py`](../register.py). That means you **cannot** reference them from YAML via `_type_: dune` (or similar) without adding registration yourself — building a config that does so will raise `ConfigError: Unknown module type 'dune'` (or `cosmos_reason2`).

| Class | File | How to make it usable |
|---|---|---|
| `DUNE` | [`backbones/vision/dune.py`](backbones/vision/dune.py) | Add a `register(registry)` function in your parent repo that imports `DUNE` and calls `registry.register_module("dune", DUNE, ...)`. Then add the parent module to `imports:` in YAML. |
| `CosmosReason2Encoder` | [`backbones/vlm/cosmos_reason2.py`](backbones/vlm/cosmos_reason2.py) | Same pattern. Requires the `transformers` package; downloads the model on first use. |

If you want them registered by default, the maintainer-side fix is to add the registrations to `../register.py` next to the other backbones.

## How to use experimental blocks from YAML

All registered keys are usable directly:

```yaml
schema_version: 1
model:
  graph:
    inputs: [cond_proprio, cond_visual, action, time, noise]
    modules:
      posterior:
        _type_: cfg_vqvae_posterior
        # ... constructor kwargs (see configs/experiments/cfg_vqvae_flow_matching.yaml)
      encoder:
        _type_: cfg_vqvae_info_encoder
        # ... constructor kwargs
      decoder:
        _type_: cfg_vqvae_action_decoder
        # ... constructor kwargs
    nodes:
      - {name: semantic, call: module:posterior, args: [$cond_proprio, $cond_visual, $action]}
      - {name: cond,     call: module:encoder,   args: [$cond_proprio, $cond_visual, $semantic]}
      - {name: out,      call: module:decoder,   args: [$time, $noise, $cond, $semantic]}
    outputs: [$out]
    return: single
```

For complete, working configs see [`../../../configs/experiments/`](../../../configs/experiments/) and the annotated walkthrough in [`../../../configs/README.md`](../../../configs/README.md).

## Listing every registered experimental block at runtime

```python
from model_constructor.registry.default_registry import get_default_registry

reg = get_default_registry()
for name in reg.list_modules():
    entry = reg.get_module(name)
    if "experimental" in entry.tags:
        print(f"{name:40s} tags={entry.tags}")
```
